# TriPlane Encoder V1/V2/V3 — initial engineering evidence

Scope: independent research implementation for `11.txt`; raw partial LiDAR XYZ only; existing Stage1 FM and geometry. A shared observed-voxel 12D statistics module and 2D depthwise/FPN pipeline feed three 128-channel ZYX volumes. V2 uses four shared-weight height planes, a coarse 64-channel 3D bridge and a 24-channel observed-voxel SubMConv residual; V3 adds distance/density/coverage-dependent zero-initialized fusion residuals. V3 has no authorized training in this round.

V1/V2/V3 max-parent real Batch2 forward/backward, finite nonzero encoder and flow gradients, output shapes/dtypes, and model/EMA checkpoint roundtrip: **GPU_PASS**. Full JSONs and data/config/source hashes: `triplane_encoder_v1_audit/gate_v*.json`. Resume continuity is tested separately as part of each 32-update smoke; no formal training claims are made until that passes.

Random-initialized inference, seq08 frame100, AMP, warm5/timed10: V1 GPU2 wall 6.94 ms and V2 GPU3 wall 18.14 ms. The results use different GPUs, a single scene, and profiling hooks; they are diagnostic, not a paired speedup, not kernel-only time, and not an end-to-end claim. Detailed spans/measurements: `triplane_encoder_v1_audit/benchmark_v*.json`. Paired E2 timing, representative-frame percentiles, kernel-only profile, model quality and post-training latency: **NOT TESTED**.

The V2 first AMP attempt failed because PyTorch autocast changed sparse features to FP16 while SpConv weights stayed FP32 (`can't find suitable algorithm`). The controlled sparse precision boundary now disables autocast and explicitly matches feature and weight dtypes; subsequent real-frame and full-Batch2 tests passed. The V3 first probe was accidentally invoked with the V1 config; it correctly rejected that identity and subsequently passed with the V2 config. No historical artifacts were altered.

V3 zero gate residual preserves V2 fusion arithmetic. Real GPU frame100, identical V2 weights: V2 repeat max differences [0.03955,0.00513,0.00098], V3 versus V2 [0.03955,0.00488,0.00055], mean errors approximately 6e-8. This is not bitwise parity and does not isolate a strict error bound across frames; the repeated V2 variation is comparable. V3 gate values initially equal 1; recorded near/mid/far diagnostic means were approximately 1. V3 needs a stricter per-layer attribution and broader parity tests before any training decision.

Registered V1/V2: scratch, separate single GPUs, real Batch2, seed 20261032, 10,000 successful updates/20,000 successful exposures, original FM objective, AdamW/EMA and E2-compatible scheduler. Each goes through a fresh two-update smoke, exact checkpoint resume to32 successful updates, then an independent random-initialized formal run; seq08 skip100/41 NFE1/2/4/8 follows automatically after successful training. No 100K or Stage2 training is added. Existing Stage2 morph-close26 and zero-extra-Parent user requirements remain in force for any future Stage2 work.

The existing single-GPU E2 run used seed 20261021, whereas `11.txt` requires seed 20261032. They share the same exposure and model-training protocol but are **not** a strictly matched same-seed cohort. Do not claim a strict paired training-seed comparison or silently change either seed. All quality data for V1/V2, Fixed-K, CD, physical IoU, per-frame gates and trained speed remain **NOT TESTED** until the actual evaluation completes.

Unit tests: `tests/test_triplane_encoder.py` and `tests/test_joint_fm_no_extra_parents.py`, 10 passed. The per-component CUDA event spans include possible host submission/synchronization gaps and must not be interpreted as pure GPU kernel arithmetic time.
