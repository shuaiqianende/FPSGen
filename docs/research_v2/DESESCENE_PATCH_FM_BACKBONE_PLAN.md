# PatchScene-inspired FM velocity backbone

Two scratch20K arms: `patch_psa` uses U1+A, `patch_psab` uses U1+A+B. Both use exactly the same independently seeded PatchFlowUNet template (seed 20261032+104729), preserving the input-only observed mask and three 128D feature scales. This is a newly adapted architecture, not PatchScene official weights or an exact reproduction of its patch diffusion model.

The velocity network accepts state x_t, observed mask, three scales and forward FM t in [0,1]. Gaussian source at t=0, binary symmetric target at t=1, FM MSE, FP32 Euler updates, NFE2 final evaluation and data protocol remain unchanged. At scales 384/192/96/48 the width is 8/16/32/64; down/up residual blocks use time embedding and original condition features are projected at 192/96/48. A 4-head spatial attention is placed at the 48-scale bottleneck. The 8/16/32/64 widths are a 3090-oriented adaptation, not the official 32-base architecture. Residual output convolutions begin at zero, so time embedding has zero gradient on the initial update; the CPU test checks that it receives nonzero gradient after the first update.

Each per-GPU queue waits for its existing BC queue to complete, checks shared GPU admission, and independently runs real batch2 max-scene gate, 32 successful update smoke, 20K scratch training, then seq08/skip100 41-frame NFE2 evaluation. Any failed check stops that arm and records its log. No 900-frame evaluation or Stage2 training. No quality, performance or VRAM result is claimed before actual GPU execution. Six CPU tests pass, including FM t boundaries, condition and time gradient, same-seed initialization, and U1+A/B checks. Formal GPU validation and both trainings are NOT YET RUN.
