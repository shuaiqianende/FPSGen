# GCTV baseline and failure diagnosis — work in progress

V1 and V2 finished 10,000 successful updates / 20,000 successful frame exposures; their 41-frame seq08 evaluations completed. Their NFE2 Parent IoU is 0.319459 and 0.325239 respectively. Historical scratch20K FM NFE2 is 0.388973, but uses different AMP/FP16 policy and warmup; this is not an architecture-only controlled comparison. V1/V2 use different tokenizer and independent input encoding. The existing 900-frame single-GPU E2 was trained with seed 20261021 rather than 20261032; it is not a strictly matched training cohort.

Code inspection: V2's coarse bridge input is formed only from grouped XY features, and bridge output is added to XY, XZ and YZ features. All three plane pyramids are subsequently fused into the output, so those plane updates are not dead code. Its high-resolution sparse residual uses only LiDAR-observed voxels, not GT support.

Across 64 spread development frames, FP32 voxel-index arithmetic assigned 27 of 1,152,000 valid input points differently from the strong encoder's FP64 arithmetic (24 affected frames, maximum three points in one frame). Example seq00 frame500: XYZ [3.62706399, 2.60416341, -1.70753694] maps to XYZ voxel [102,100,4] in the original versus [102,101,4] in TriPlane. This is a real boundary difference; causation of the much larger quality gap is NOT ESTABLISHED. G0/G1/G2 share the original FP64 index calculation; historical V1/V2 retain their original FP32 indexing in diagnostics. No old weights were changed.

User correction: all future diagnostics/evaluations use seq08/skip100 (41 frames). The two previously started 900-frame jobs and their queue were stopped on request; each had completed 82 frames and partial artifacts are preserved, not counted as results. The diagnostic script now hard-limits inputs to `08/000000..004000` stride100, and the GCTV configurations explicitly disable the old 900-frame automatic evaluation.

Per-frame 41-frame threshold curves, fixed-K, radial/observed splits, CD and time-stratified velocity errors are running via `audit_gctv_baseline_900.py` (historical filename, now hard-limited to41). The 101-threshold PR-AUC is a discretized approximation, not exact ranking AP. Threshold sweep is exploratory and is not independent threshold calibration. Raw labels, no GT condition leakage, original 50m geometry. Velocity-output gradient magnitude is recorded, not the parameter-gradient decomposition; height-layer and structural region labels: NOT TESTED. Strictly matched training reference and attribution of failure: NOT TESTED until complete.
